# On-demand ISR pages leak the generating request's query string

Minimal reproduction for a Next.js App Router bug when self-hosting with `next start`.

A fully static page that is generated on demand at runtime (ISR) is rendered with the query string of whichever request
triggered the render. Next.js embeds that query string in the cached RSC payload: the initial canonical URL (`c`) and
the rendered search (`q`). The cached page, containing that one visitor's query string, is then served to every later
visitor, whatever query string they used.

Pages generated at build time are not affected, because they are rendered with an empty query.

## Run

```sh
npm install
npm run build
npm run repro
```

`npm run repro` starts `next start` on port 3123 and requests each page as three visitors:

1. Visitor A: `?utm_source=ad&click_id=alice-private-click-id`, the first request for the page
2. Visitor B: no query string
3. Visitor C: `?click_id=bob`

It exits with code 1 if visitor B or C receives visitor A's query string.

## App

- [`app/[slug]/page.tsx`](app/%5Bslug%5D/page.tsx) is a static page. It uses no `searchParams` or other dynamic APIs.
  - `/prerendered` is listed in `generateStaticParams`, so it is generated at build time (the control).
  - `/on-demand` is not listed, so it is generated on demand at runtime (`dynamicParams` defaults to `true`).
- There is no custom server, middleware or config.

## Output (next@16.4.3, node v20.18.1)

```
/prerendered (generated at build time)
  Visitor A  GET /prerendered?utm_source=ad&click_id=alice-private-click-id x-nextjs-cache=HIT   (own request)
  Visitor B  GET /prerendered                                            x-nextjs-cache=HIT   clean
  Visitor C  GET /prerendered?click_id=bob                               x-nextjs-cache=HIT   clean

/on-demand (generated at runtime by visitor A, then cached)
  Visitor A  GET /on-demand?utm_source=ad&click_id=alice-private-click-id x-nextjs-cache=MISS  (own request)
  Visitor B  GET /on-demand                                              x-nextjs-cache=HIT   LEAKED visitor A's query
             ...0:{\"P\":null,\"c\":[\"\",\"on-demand?utm_source=ad&click_id=alice-private-click-id\"],\"q\":...
  Visitor C  GET /on-demand?click_id=bob                                 x-nextjs-cache=HIT   LEAKED visitor A's query
             ...0:{\"P\":null,\"c\":[\"\",\"on-demand?utm_source=ad&click_id=alice-private-click-id\"],\"q\":...

BUG REPRODUCED: visitors B and C received visitor A's query string ("alice-private-click-id") in the cached page.
```

The same happens when the page is first generated by a client-side navigation (RSC) request. The cached RSC response
and the HTML served to later visitors both contain the first visitor's query string.
